## 2. 프로젝트를 내 컴퓨터로 가져오기

VS Code 에서:

1. 첫 화면의 **Clone Git Repository...** 클릭
   (안 보이면 왼쪽 세 번째 아이콘 🔀 → **Clone Repository**)
2. 맨 위 입력칸에 **내가 맡은 쪽** 주소 붙여넣기 → Enter
   - 화면(프론트엔드): `https://github.com/philip0613/programing-in-pajama`
   - 서버(백엔드): `https://github.com/philip0613/program-in-pazama`
3. 저장할 폴더 고르기 (예: `문서`) → **Select as Repository Destination**
4. 오른쪽 아래 **Open** 클릭 → 끝!

### 📂 프로젝트 폴더 여는 법 (더블클릭할 파일이 있는 곳)
VS Code 왼쪽 파일 목록에서 아무 파일이나 **우클릭 → Reveal in File Explorer** (맥: Reveal in Finder)
→ 열린 폴더에 아래 4개 파일이 있어요. **이게 전부예요!**

| 파일 | 언제 | 하는 일 |
|---|---|---|
| **`작업시작.bat`** | 새 작업 시작할 때 | 최신 코드 받고, 내 작업 공간 만들기 |
| **`실행하기.bat`** | 화면/서버 띄워볼 때 | 설치 + 실행 (까만 창은 닫지 말기) |
| **`올리기.bat`** | 작업 끝났을 때 | 저장 + GitHub 에 올리기 + "합쳐주세요" 페이지 열기 |
| **`최신받기.bat`** | 친구 작업 받아올 때 | 친구들이 합친 최신 코드 받기 |

> 🍎 맥은 `맥용` 폴더 안의 `.command` 파일을 쓰세요. 처음엔 **우클릭 → 열기** 로 실행해야 해요.

## 3. ⭐ 매일 작업하는 순서

### ① `작업시작.bat` 더블클릭
- "무슨 작업을 하나요?" → `댓글 기능` 처럼 짧게 입력 → Enter
- ✅ "작업 공간을 만들었어요!" 가 나오면 성공. 창을 닫으세요

### ② `실행하기.bat` 더블클릭 (확인하면서 고치고 싶을 때)
- 화면은 브라우저가 자동으로 열려요. **코드를 고치면 바로 반영**돼요
- 까만 창을 닫으면 꺼져요

### ③ VS Code 에서 코드 고치기
- 고친 다음 **Ctrl + S** 로 저장 (안 하면 안 올라가요!)

### ④ `올리기.bat` 더블클릭
- 바뀐 파일 목록이 나와요
- "무엇을 했는지 한 줄로" → `댓글 목록 화면 추가` 처럼 입력 → Enter
- **처음 한 번만:** GitHub 아이디와 이메일을 물어보고, **GitHub 로그인 창**이 떠요 → **Sign in with your browser** 로 로그인
- 브라우저가 열리면 초록 **Create pull request** 클릭 → 단톡방에 링크 공유!

> 💡 하루에 ③④ 를 여러 번 반복해도 돼요. Create pull request 는 처음 한 번만 누르면, 그 뒤에 올린 건 자동으로 같은 요청에 추가돼요.
> 💡 기능이 다 합쳐지면, 다음 작업은 다시 ① `작업시작` 부터!

## 4. 🧪 내가 만든 거 테스트하기

> **올리기 전에 꼭 직접 확인하기!** 내 컴퓨터에서 확인한 것만 올려요.

### 🖥 화면(프론트엔드) 담당
1. **`실행하기.bat`** → 브라우저가 자동으로 열려요
2. 코드를 고치고 **Ctrl + S** → 브라우저 화면이 **자동으로 바뀌어요** (새로고침 필요 없음)
3. 화면이 하얗게 나오거나 이상하면 → 브라우저에서 **F12** → **Console** 탭의 빨간 글씨를 캡처해서 단톡방에

**어떤 서버랑 연결할지** 는 `.env` 의 `VITE_BACKEND_URL` 로 골라요 (바꾼 뒤엔 까만 창 닫고 다시 실행)

| 상황 | 설정 |
|---|---|
| 평소 (추천) | `https://program-in-pazama.onrender.com` — 실서버 사용, 백엔드 안 켜도 됨 |
| 서버 친구가 아직 안 올린 새 API 를 같이 테스트 | `http://localhost:8080` + 백엔드 폴더의 `실행하기.bat` 도 켜기 |
| 서버가 아직 없음 | 맨 아래 `VITE_USE_MOCK=true` (가짜 데이터) |

> ⚠️ 실서버에 연결하면 **글쓰기 등이 실제 사이트에 저장돼요.** 테스트 글은 제목에 `[테스트]` 를 붙여주세요.
> 💡 화면 맨 위 상자가 ✅ 초록색이면 서버 연결 OK. 💤 안내가 뜨면 무료 서버가 깨어나는 중이니 1분만 기다리기

### ⚙️ 서버(백엔드) 담당
1. **`실행하기.bat`** → 서버가 켜져요. 코드를 고치고 **Ctrl + S** 하면 **자동으로 재시작**돼요
2. VS Code 에서 **`api-test.http`** 파일 열기
   - 처음 열면 오른쪽 아래에 **"권장 확장 설치"** 알림 → **설치** (REST Client)
3. 각 요청 위의 작은 글씨 **Send Request** 클릭 → 오른쪽에 서버 응답이 떠요
   - `200` / `201` = 성공, `400` = 요청이 잘못됨, `500` = 서버 코드 에러
4. **로그인이 필요한 API** 는 백엔드 담당 친구가 `api-test.http` 에 적어둔 순서대로 테스트하세요 (토큰을 먼저 받는 요청부터 Send)
5. 에러가 나면 **까만 창**(서버 창)에 빨간 글씨가 나와요 → 캡처해서 단톡방에

**새 API 를 만들었다면:** `api-test.http` 맨 아래에 요청을 추가하고, `docs/API.md` 에 명세도 적어서 같이 올려주세요. 화면 친구가 그걸 보고 연결해요.

> ⚠️ DB 가 실제 사이트와 같아서, 테스트로 쓴 글이 실제 사이트에도 보여요. 제목에 `[테스트]` 를 붙여주세요.
> 💡 **GET 요청**은 브라우저 주소창에 바로 넣어도 돼요 (예: http://localhost:8080/api/test)

### 🤝 화면 + 서버 같이 확인하기
1. 백엔드 폴더 **`실행하기.bat`** + 프론트 폴더 **`실행하기.bat`** 둘 다 켜기
2. 프론트 `.env` 의 `VITE_BACKEND_URL=http://localhost:8080`
3. 브라우저에서 실제로 눌러보기

### ✅ PR 올리면 자동 검사
`올리기` 후 PR 페이지 아래쪽에 **자동 검사(CI)** 결과가 떠요. ❌ 빨간색이면 화면은 빌드(배포용 변환)가 실패한 거고, 서버는 서버가 켜지지 않는 거예요. 캡처해서 단톡방에!

## 5. 친구 작업 확인하고 합쳐주기

친구가 "합쳐주세요" 요청(PR)을 올렸다면 (GitHub 웹사이트에서):

1. 레포 페이지 → 위쪽 **Pull requests** 탭 → 친구 PR 클릭
2. **Files changed** 탭에서 바뀐 내용 훑어보기 (초록 줄 = 추가, 빨간 줄 = 삭제)
3. 아래 **CI** 체크가 ✅ 초록색인지 확인 (❌ 빨간색이면 친구에게 알려주기)
4. 괜찮으면 **Review changes → Approve → Submit review**
5. **Merge pull request → Confirm merge**

> ⚠️ **Merge 하면 실제 사이트에 바로 반영돼요.** 확실하지 않으면 단톡방에 먼저 물어보기!
> 💡 내 요청은 내가 승인(Approve) 못 해요. 다른 친구가 해줘야 해요.

## 6. 키값 넣기 / 목 모드

### 🔑 키값 넣기 (로그인·DB 기능 쓰려면)
1. `실행하기.bat` 을 한 번 실행하면 폴더에 **`.env`** 파일이 생겨요
2. VS Code 왼쪽 파일 목록에서 `.env` 클릭
3. 단톡방에서 받은 키값을 `=` 뒤에 붙여넣고 **Ctrl + S**
4. 까만 창을 닫고 `실행하기.bat` 다시 실행

> ⚠️ `.env` 는 비밀 파일이라 `올리기` 를 해도 GitHub 에 안 올라가게 설정돼 있어요.

### 🧪 화면 담당인데 서버가 아직 없다면? (목 모드)
`.env` 에서 `VITE_USE_MOCK=false` 를 `VITE_USE_MOCK=true` 로 바꾸고 다시 실행하면, 가짜 데이터로 화면을 만들 수 있어요.

## 7. 자주 생기는 문제

| 증상 | 해결 |
|---|---|
| "Node.js 가 설치되어 있지 않아요" | 1-② 설치 후 **컴퓨터 재시작** |
| "Git 이 설치되어 있지 않아요" | 1-③ 설치 후 **컴퓨터 재시작** |
| "아직 올리지 않은 수정 내용이 있어요" | `올리기.bat` 먼저 하고 다시 시도 |
| "다른 친구가 같은 부분을 고쳐서…(충돌)" | 내 작업은 안전해요. **캡처해서 단톡방에!** 같이 정리해요 |
| "올리기에 실패했어요" | 초대 메일 수락했는지 확인 → 그래도 안 되면 캡처해서 단톡방에 |
| `Port 5173 is already in use` / `EADDRINUSE` | 이미 켜진 까만 창이 있어요. 그 창을 닫고 다시 실행 |
| 화면에 "❌ 백엔드 연결 실패" | 서버 폴더의 `실행하기.bat` 도 같이 켜거나, 목 모드 사용 |
| "로그인할 수 없습니다" | `.env` 에 키값을 안 넣었어요 (6번 참고) |
| 실수로 `작업시작` 안 하고 고쳤어요 | 괜찮아요! `올리기` 가 알아서 작업 공간을 만들어서 올려줘요 |

## 8. 용어 사전

| 용어 | 쉽게 말하면 |
|---|---|
| **레포 (Repository)** | 프로젝트 폴더. 우리는 화면용 1개, 서버용 1개 |
| **`main`** | 원본. 실제 사이트와 연결돼 있어서 직접 건드리지 않기! |
| **브랜치 (Branch)** | 내 작업 공간. 여기서 뭘 해도 원본과 친구들에게 영향 없음 |
| **커밋 (Commit)** | "여기까지 저장" 찍기 (게임 세이브) |
| **푸시 (Push)** | 내 작업을 GitHub 에 올리기 |
| **풀 (Pull)** | GitHub 의 최신 코드를 내 컴퓨터로 받기 |
| **PR (Pull Request)** | "내 작업을 원본에 합쳐주세요" 요청서 |
| **머지 (Merge)** | 요청을 승인해서 원본에 합치기 |
| **충돌 (Conflict)** | 두 사람이 같은 줄을 다르게 고쳐서 자동으로 못 합치는 상황 |

> 🙋 `작업시작` = 브랜치 만들기 · `올리기` = 커밋 + 푸시 · `최신받기` = 풀
